更新日期：2026-10-14
功能细节和 API 参数见 [FEATURES.md](FEATURES.md)，本文只讲怎么做、按什么顺序做。

变更记录：

- 2026-10-14 第三版：移除 Anime V3 和 Furry V3（基本已弃用），连同 DDIM、native 噪声计划、SMEA、Decrisper、UC 强度一起去掉；旧存档里的 V3 节点会换成 V5 Full
- 2026-10-14 第二版：画布引擎从 tldraw 换成 React Flow；交互改为照 FLORA 的手感来做；外观定为 FLORA × Nothing OS；新增第三节"视觉与动效"。原因：用户试用后觉得 tldraw 的手感和交互不如 FLORA，并且喜欢 Nothing OS 的界面风格。

## 已确定的方向

- 先给自己用，在本机运行
- 界面采用无限画布加功能节点
  - **交互**照 FLORA 来做：操作方式、节点结构、连线方式都以它为准
  - **外观**是 FLORA 的卡片式节点，加上 Nothing OS 的视觉语言：点阵、黑白灰、红色点缀、点阵字体
  - **画布引擎**用 React Flow，FLORA 用的也是它
- 生成的图片存在本机专用文件夹（默认 `E:\NAI\outputs`，可在设置里改）
- 支持明亮和暗色两套主题，默认跟随系统
- 要有克制但有生命力的小动效，具体规范见第三节
- 交互要人性化，具体约定见第五节

## 一、整体架构

```text
浏览器  http://localhost
 ├─ 画布：React Flow 12（@xyflow/react），节点全部自定义
 ├─ 界面：React + TypeScript + Vite，Radix UI 无样式组件，套上自己的视觉风格
 ├─ 动效：CSS 过渡为主；需要弹簧效果和进出场动画的地方用 Motion（motion.dev）
 ├─ 提示词编辑器：CodeMirror 6（高亮、补全、@片段、token 计数）
 └─ 应用状态：Zustand（画布节点和连线也放在这里，React Flow 只负责显示和交互）
          │ HTTP + SSE
本地服务  Node 24 + Hono（TypeScript）
 ├─ 代理 NovelAI API：Token 只存在本机配置文件里，不进浏览器
 ├─ 图片落盘：outputs/日期/文件名.png，保留官方元数据
 ├─ 项目文件：data/projects/*.json，画布自动保存
 ├─ 图库索引：SQLite（Node 自带的 node:sqlite），可扫描 outputs 文件夹重建
 └─ 其他数据：Vibe 编码缓存、提示词片段、设置
```

为什么要加一个本地服务，而不是让浏览器直接调 NovelAI：

- 浏览器不能随意往本地文件夹写文件，本地服务可以
- 生成到一半关掉网页，图片照样保存
- Token 不放在浏览器里
- 图库索引、缩略图、读取图片像素（解析隐写元数据）都放在服务端做，更方便

为什么从 tldraw 换成 React Flow：

- FLORA 本身就建立在 React Flow 上，要做出它的手感，用同一个底层最直接
- React Flow 自带端口、连线、框选、小地图，节点里放输入框、滑块也不会和拖拽冲突
- MIT 协议，没有授权码，也没有水印
- tldraw 白送的便签、箭头、框要自己做，改成"便签节点"和"分区"（见第二节）

执行引擎（按依赖顺序运行节点）要自己写，规模不大：拓扑排序，加一个串行的 NovelAI 请求队列。

### 目录结构

```text
E:\NAI\
├─ docs\          FEATURES.md、PLAN.md
├─ web\           前端（Vite + React + React Flow）
├─ server\        本地服务（Node + Hono）
├─ shared\        前后端共用的代码：模型能力表、预设、计费公式、类型定义
├─ outputs\       生成的图片
├─ data\          config.json、projects\、vibes\、library.db（不进 git）

```

用 pnpm workspace 管理。核心规则写成纯函数放在 `shared\`，用 Vitest 做单元测试，包括计费公式、质量标签和 UC 预设的拼接、随机器、元数据解析、执行顺序。

## 二、节点设计

基本思路不变：**单个节点就能完成生图，复杂需求再接线**。

### 节点的结构（照 FLORA）

```text
  ■ 生图 1                     GENERATING · 07/28   ← 标题和状态在卡片上方
 ┌────────────────────────────┐
 │                            │
 │      结果图（卡片主体）       │  ← 悬停时上方出现节点工具条
(+)                          (+) ← 左右各一个 + 手柄
 │                            │
 ├────────────────────────────┤
 │ ◆ 角色 1 ×   ■ 底图 ×        │  ← 已接入的输入，显示成小标签
 │ 约 120/1471 TOKEN  ( ↑ 生成 )│  ← token 数 + 红色「生成」按钮
 │ [参数] V5 FULL · 832×1216 · 28 步 │  ← 参数摘要，点一下在右边打开参数卡片
 └────────────────────────────┘
   [▢][▢][▢][▢]                  ← 历史缩略图条，2 张以上才出现
```

- **卡片主体就是内容**：生图节点显示结果图，提示词节点显示文字，图片节点显示图片
- **提示词从提示词节点接进来**：生图节点自己没有提示词框（2026-10-15 去掉的，免得框里忘了清的内容混进去）。底栏左边是 token 数，没接提示词时换成「新建提示词」；右边是红色的「生成」按钮，悬停显示本次消耗
- **详细参数放在参数卡片里**：点卡片最下面的「参数」或按 P，参数卡片贴在生图卡片右边打开，和生图卡片是同一个节点、一起拖动。生图卡片本身只放结果图、输入标签和一行参数摘要，保持干净
- **只有两个连接手柄**：左边是输入，右边是输出，悬停时变成 `+`
  - 从 `+` 拖出连线，松在另一个节点上，会按数据类型自动接到对应的输入：文本接提示词，图片接底图，角色接角色，风格接风格参考
  - 松在空白处，弹出能接上的节点
  - 不用找端口，也不会出现端口挡住文字的问题
- **接入的输入显示成小标签**：可以点 × 断开，拖动标签调整顺序（比如多个风格参考的先后）。悬停标签时高亮对应的连线和来源节点
- **悬停节点时，上方出现节点工具条**：运行、复制、删除，以及该类节点的专属操作
- **历史缩略图条**：同一个节点生成 2 张以上时出现在卡片下方。左右方向键切换，选中的那张就是传给下游节点的图
- **调整大小**：选中或悬停节点时，右下角圆角外侧出现一段弧形手柄，拖动即可改变大小。带图的节点只调宽度，高度按图片比例自动变；文字节点宽度和高度都能调。双击手柄恢复默认大小，可以撤销
- **节点状态**写在卡片上方：排队中、生成中（步数和预计剩余时间）、失败（卡片里显示中文原因和改法）

### 节点列表

| 节点 | 卡片主体 | 可接入 → 输出 |
|---|---|---|
| **生图** | 结果图、输入标签、生成按钮、参数摘要；参数在旁边的参数卡片 | 提示词（多个）、画师串（多个）、负面提示词（多个）、角色（多个）、底图、遮罩、风格参考（多个）、精确参考（多个）→ 图片 |
| **提示词** | 一段可复用的提示词，可以同时连到多个生图节点 | → 文本 |
| **角色** | 角色提示词、UC、启用开关，5×5 点阵选位置（V5 可自由摆放） | → 角色 |
| **图片** | 上传、拖入、粘贴，或从结果里拖出。显示元数据标记 | → 图片 |
| **风格参考**（Vibe） | 强度、信息提取量；自动编码并缓存 | 图片 → 风格参考 |
| **精确参考** | 类型、强度、保真度（仅 V4.5） | 图片 → 精确参考 |
| **增强** | 幅度和放大倍率，结果显示在卡片里 | 图片 → 图片 |
| **放大** | | 图片 → 图片 |
| **Director Tools** | 去背景、去杂物、线稿、草图、上色、表情、像素整理，每种一个节点 | 图片 → 图片 |
| **网格生成** | 包住一个生图节点，按 X/Y 两个轴改参数批量出图 | 生图节点 → 多张图片 |
| **便签** | 纯文字标注，可选颜色 | 无 |
| **分区** | 把一组节点框在一起，可命名、整体移动、一键运行整个分区（FLORA 的 Field） | 无 |

关于局部重绘、图生图和变体：它们不单独做成节点，而是生图节点的不同用法。

- 接上底图就是图生图，再接上遮罩就是局部重绘，节点会自动换用对应的 inpainting 模型
- 在结果图上点"局部重绘"、"变体"等快捷操作，会自动创建一个连好线、参数已填好的新节点，并直接打开遮罩编辑器

这样画布上的节点和连线本身就是一份可视化的创作历史。

### 画布之外的界面

- **左上**：项目名和保存状态
- **右上**：Anlas 余额、Opus 额度点阵条、主题切换、设置入口
- **底部中间的工具坞**：添加节点、撤销重做、缩放和适配、快捷键说明。每个按钮都带文字，不只放图标
- **右侧参数面板**：选中生图节点时滑出；选中多个同类节点时变成批量编辑，数值不同的项显示"混合"
- **选中多个节点时**：出现选区工具条，可以全部运行、全部删除
- **图库**：底栏按钮打开全屏图库，也可以钉到画布上变成图库节点，图可以拖到画布上（阶段 6、7）

## 三、视觉与动效（FLORA × Nothing OS）

### 视觉语言

- **颜色**：只用黑、白、灰。红色只表示三件事：主操作（运行按钮）、正在发生（生成中、连线流动）、被选中的值（角色位置点）。不用红色做装饰
- **点阵**：画布背景是点阵；进度条、额度条、角色位置、空白状态都用点来表达；连线画成点线
- **字体**：
  - 点阵字体 Doto，只用在数字和英文大标题（余额、步数、缩放比例、空白状态）
  - 正文用 Geist，中文回退到 Noto Sans SC
  - 标签和参数值用 Geist Mono，英文全大写并加字距
- **形状**：节点是大圆角卡片（约 24px）；按钮和分段选择器是胶囊形；手柄和状态点是正圆
- **两套主题**：明亮是浅灰底加白卡片；暗色是纯黑底加深灰卡片。两套主题都要单独检查对比度

### 动效规范

原则：动效是为了反馈和让界面"活着"，不能拖慢操作。所有动效在系统开启"减少动态效果"时关闭。

| 场景 | 动效 | 时长 |
|---|---|---|
| 新建节点 | 从 94% 弹性放大到 100%，淡入 | 约 320ms |
| 删除节点 | 缩小淡出 | 160ms |
| 建立连线 | 点线从起点"画"到终点 | 约 450ms |
| 拖线时 | 点沿着连线流向鼠标；能接的节点描红边，手柄脉动 | 持续 |
| 悬停节点 | `+` 手柄从小点弹出；工具条淡入上移 | 150ms |
| 生成中 | 卡片边框有一道红光绕圈（致敬 Glyph 灯带）；输入连线变红并流动；点阵噪声逐步收敛成图 | 持续 |
| 生成完成 | 结果定格时闪一下；余额数字滚动减少；额度条的点逐个熄灭 | 约 600ms |
| 空白的生图节点 | 点阵缓慢起伏，像在呼吸 | 持续，低帧率 |
| 鼠标在画布上移动 | 光标附近的背景点略微变大变深 | 跟随 |
| 分段选择器、开关 | 选中块平滑滑动；开关圆点带弹性 | 180ms |
| 菜单、面板、提示条 | 从触发位置缩放展开；侧栏滑入；提示条上滑 | 150–220ms |

技术上，跟随鼠标、持续动画都用 CSS 变量或 canvas，按需暂停（不在视野里、页面隐藏时不跑）。

## 五、交互约定（照 FLORA，所有阶段都遵守）

### 鼠标和触控板

| 操作 | 效果 |
|---|---|
| 左键拖动节点 | 移动节点（选中多个时一起移动） |
| 左键拖动空白处 | 框选 |
| 从 `+` 手柄拖出 | 拉出连线 |
| 右键拖动、中键拖动、按住空格拖动 | 平移画布 |
| 滚轮、触控板双指滑动 | 平移画布 |
| Ctrl+滚轮、双指捏合 | 缩放（设置里可以改成滚轮直接缩放，适合鼠标用户） |
| 双击空白处 | 在该位置添加节点 |
| 右键单击 | 打开菜单：节点上是节点操作，空白处是添加节点 |
| Shift+单击 | 加选或减选 |

### 快捷键

| 按键 | 效果 |
|---|---|
| Enter | 运行选中的节点；在工具节点的提示词里按 Enter 也是运行 |
| Shift+Enter | 在工具节点的提示词里换行 |
| Delete / Backspace | 删除选中的节点或连线 |
| Ctrl+D | 原地复制选中的节点，副本放到右侧空位，从外部接入的连线一并保留 |
| Ctrl+C / Ctrl+V | 只管文字和图片，不复制粘贴节点；剪贴板里是图片时，粘贴成图片节点（选中图片节点时替换它的图）。节点要带到别的画布用右键菜单 |
| Alt+拖动 | 拖出一份副本，原节点不动 |
| Ctrl+Z / Ctrl+Shift+Z | 撤销、重做 |
| Ctrl+F | 搜索画布上的节点 |
| ← / → | 在选中节点的历史缩略图之间切换 |
| H | 隐藏或显示选中生图节点的底栏（输入标签、生成按钮、参数行），让画布更干净 |
| P | 展开或收起选中生图节点的参数卡片 |
| Shift+1 | 适配全部节点 |
| ? | 显示快捷键表 |

### 人性化约定

1. **开箱即用**：新建画布时自带"提示词 → 生图"的模板，不需要从零开始连线
2. **添加节点不用找**：双击空白处、从 `+` 拖到空白处、右键、底部工具坞，四种方式都能添加；菜单里每个节点都有一句话说明
3. **节点永不重叠**：拖动时贴近其他节点的边缘或中线会吸附，并显示红色虚线对齐线（按住 Ctrl 不吸附）；松手时如果压到别的节点，会自动滑到最近的空位，拖动途中用虚线框预告落点。新建、复制、粘贴的节点也会自动找空位；把节点拉大压住邻居时，邻居会被让开
4. **连线不用对准**：连线松在目标节点的任意位置都行，按类型自动接到对应输入；接不上的节点在拖线时变暗
5. **拖进来就能用**：普通图片变成图片节点；NovelAI 生成的图询问要不要还原整套节点；粘贴图片同理
6. **复杂度按需展开**：节点只放提示词和参数摘要，详细参数在右侧面板；当前模型不支持的选项直接隐藏
7. **花多少钱提前说**：运行按钮悬停显示消耗；余额不够或设置超限时提前提示，不等到报错
8. **过程看得见**：卡片上方显示状态和预计时间；生成时显示中间步骤；随时可以取消；失败时用中文说明原因和改法，失败的点数自动退回
9. **不会丢东西**：所有操作都可撤销；画布自动保存；图片生成后立刻写入硬盘
10. **快捷操作会自动连线**：在结果图上点"增强"、"重绘"、"放大"等，会自动创建一个连好线的节点
11. **两套主题都好看**：每个组件都在明亮和暗色下检查一遍

## 六、风险与注意事项

- **NovelAI 的规则**：生成请求必须由人手动触发。网格生成和批量生成都由你点击启动，不做无人值守的自动连发。请求一律排队，避免并发被拒
- **React Flow 版本**：开发期间锁定版本，升级时单独处理
- **动效和性能**：画布上图片多时，持续动画只在可见的节点上运行；提供关闭动效的设置
- **分词器不确定**：V5 具体用的是哪个版本的 Qwen 分词器还不确定，token 计数可能有误差，界面上要标注"约"
- **官方功能会变**：每个阶段开始前，先对照官网和 API 文档复核一遍
- **存储可替换**：图片存储做成可替换的接口，以后想改存到别处时不用大改

## 七、开始前需要你准备

- **NovelAI 的 Persistent API Token**：在官网的账号设置里，Account 页面有 "Get Persistent API Token"。阶段 0 做好设置页后，由你自己填进去。**不要把 Token 发到聊天里**
- **输出文件夹**：已确认默认放在 `E:\NAI\outputs`
